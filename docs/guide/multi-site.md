# 同机多站点

一台服务器上想跑多个站时，先分清目标，再选方案。单站安装请先看 [部署指南](./deploy.md)。

| 你想要的 | 选哪个 |
|---|---|
| 多家互不相关的发卡站（账本、卡密、支付、管理员都分开） | **方案 A：多实例** |
| 同一主站下多个域名白标（共享进货与超管） | **方案 B：单实例分站** |
| 一库一 schema / 一租户一库 | **产品不做**（请用方案 A） |

---

## 方案 A：多实例（独立站点）

多家互不相干的店用宝塔插件 **卡栈部署**。每个域名点一次部署，得到自己的目录、端口、SQLite、密钥和进程守护。`kazhan-install.sh` 只装单站，不要拿它在同一台机器上重复装多站。

先在软件商店装好 Nginx。打开插件后：

1. 若进程守护管理器还没装，插件会按面板流程安装。
2. 填主域名（可加附加域名），运行目录默认 `/www/wwwroot/该域名`，启动用户默认 `www`。
3. 插件下载程序、写入只监听本机的配置、创建网站并反代，再登记一条独立的守护进程。
4. 浏览器打开 `http://该域名/install` 完成向导。
5. 下一家店换一个域名，再部署一次。

各站默认 SQLite，数据在自己的 `data/kazhan.db`。Redis 用宝塔本机实例，队列前缀按站点分开，避免任务串到别的店。更新、重启都在插件里对应该域名操作。

当前暂不提供 Docker 多站方案。

### 必须避免

1. 不要把两家店放进同一个运行目录或同一份配置。  
2. 不要用 `kazhan-install.sh` 再装第二站。  
3. 不要多站共用同一套卡密 / 数据加密密钥。  
4. 反代必须把正确的 `Host` 传给后端。

### 怎么验收

- 两个域名打开后，数据互不可见  
- 停掉站点 A，站点 B 仍可用  
- 各站更新只影响本站

## 方案 B：单实例 + 分站（白标）

只安装**一套**卡栈，用行级分站给不同域名换皮。适合加盟 / 分销；**不适合**两家完全独立的商户。

产品内租户模式只有行级（`tenancy.mode=row`），与用 SQLite 还是 MySQL 无关。  
分站卖主站货并可加价；开通、域名、加价等操作见 [分站（白标）](../features/subsite.md)。

| 适合 | 不适合 |
|---|---|
| 主站 + 多个换皮域名 | 要完全独立的两家店 |
| 统一进货、统一超管 | 要求密钥 / 支付商户号物理隔离 |
| 省内存与进程数 | 要单独拆走某一站单独升级 |

---

## 两方案对比

| | A 多实例 | B 单实例分站 |
|---|---|---|
| 进程 | 每站一个 | 一个 |
| 数据隔离 | 强（分目录 / 分库） | 同行级（同库） |
| 密钥 / 支付 | 可完全独立 | 共用进程密钥 |
| 升级 | 逐站 | 一次 |
| 怎么装 | 宝塔插件，每个域名部署一次 | 一键脚本或插件装一套即可 |
