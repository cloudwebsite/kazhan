# 支付渠道总览

卡栈通过「支付渠道」对接多种收款方式。  
**先配好站点公网地址，再开渠道，再用小额单验收。**

![支付渠道](/images/admin-payment.png)

*界面说明：* 卡片列出已添加驱动；可配置、启停、删除。同一类型可加多条渠道；新渠道默认停用，配好密钥后再启用，并勾选购买/充值等用途。

后台路径：**支付渠道 → 添加渠道**。

## 添加渠道的通用步骤

1. **系统设置 → 站点基础**：站点地址 = 顾客访问的 `https://域名`。  
2. 支付渠道 → 添加 → 选驱动 → 填网关/APPID/密钥。  
3. 设置手续费、排序、图标（可选）。  
4. 勾选用途（若有）：商品购买 / 会员充值 / 供货充值。  
5. **启用** → 前台下单页应出现该方式。  
6. 小额真实支付一笔，确认回调到账与发卡/入账。

密钥加密保存，编辑时留空表示不修改。

---

## 回调与反代

- 回调地址一般由系统按站点地址自动生成，无需手写死。  
- Nginx/面板反代必须传递 `Host`、`X-Forwarded-Proto`。  
- 不要对支付回调 URL 做缓存。

---

## 手续费与展示

- 手续费可按固定金额或比例配置（以后台为准）。  
- 提交给部分网关的金额可能 **含顾客承担的手续费**（如部分加密货币渠道文档所述）。  
- 改手续费不影响已经创建的支付单快照。

---

## 多币种

- 基础货币在 **系统设置 → 语言货币**。  
- 仅支持 CNY 的驱动，在基础货币不是 CNY 时可能拒绝收款。  
- Stripe / PayPal 等按渠道规则换算；以建单时快照核对回调。

---

## 排障

| 现象 | 检查 |
|---|---|
| 前台没有支付方式 | 渠道是否启用；用途是否勾选购买；主题是否隐藏入口 |
| 能下单不到账 | 站点地址、回调是否达服务器、渠道验签、防火墙 |
| 重复点击多次扣款 | 看是否同一支付单；到渠道后台对流水；本站是否待核对 |
| Docker/本机调试 | 公网回调需内网穿透或渠道沙箱能力 |
