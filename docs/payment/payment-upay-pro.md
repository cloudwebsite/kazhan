# UPAY PRO 支付渠道

返回 [支付总览](./)。

用于数字货币收款（如 USDT 多链）。与 GM Pay（`epusdt`）、BEpusdt 是**不同渠道**，配置和历史单互不影响。

## 站长三步

1. 先准备好可访问的 UPAY PRO 网关，并在网关后台配好钱包与汇率。  
2. 卡栈后台 **支付渠道 → 添加 → UPAY PRO**，填网关根地址与通信密钥，勾选要用的币种/网络，启用。  
3. 确认系统「站点地址」是公网 HTTPS，下一笔小额测试单：跳转收银台 → 付款 → 自动到账发卡/充值。

官方说明：[UPAY PRO](https://github.com/auvqiao/UPAY_PRO) · [支付接口 API](https://github.com/auvqiao/UPAY_PRO/blob/main/支付接口API文档.md)

## 后台字段

在「支付渠道」添加 **UPAY PRO**，填写：

| 字段 | 说明 |
| --- | --- |
| 网关地址 | UPAY PRO 服务根地址，例如 `https://pay.example.com`，不带 `/api/create_order` |
| 通信密钥 | UPAY PRO 后台的 `SecretKey`；加密存储，不回显，编辑时留空保留原值 |
| 收款币种与网络 | 支持多选，默认勾选 `USDT-TRC20`；仅勾选已在网关配置钱包及汇率的组合 |
| 本地支付期限 | 默认 1200 秒，范围 60–3600 秒；最终期限取本地期限、商品订单期限、网关有效期的最早值 |

网关期限还需在 UPAY PRO 后台配置，本接口没有设置上游期限或关闭交易的参数。本地停止展示收银台不会关闭已经打开的上游页面，迟到款项按下文处理。

支持 `USDT-TRC20`、`TRX`、`USDT-Polygon`、`USDT-BSC`、`USDT-ERC20`、`USDT-ArbitrumOne`、`USDC-ERC20`、`USDC-Polygon`、`USDC-BSC`、`USDC-ArbitrumOne`。同一渠道可勾选多个组合，商城在商品付款、会员充值和供货充值中展示对应选项。顾客先选择币种与网络，后端校验该组合已启用后，将其作为 `type` 创建上游订单，再跳转返回的 `payment_url`。多选时必须指定选项，不会静默使用默认链。

旧配置 `trade_type` 自动按原值兼容，后台重新保存后使用 `trade_types` 数组。不会自动启用其他网络。仅一种组合时兼容旧客户端省略选择；多种组合需主题传递渠道列表中的 `methods[].code` 作为 `method`。

支持商品购买、会员余额充值、供货账户充值，可分别开关用途。手续费、费用承担方、推荐和排序沿用现有设置。**提交网关的金额是含顾客手续费的 CNY 金额**，由网关汇率换算为链上币种。

站点必须有可从公网访问的 HTTP(S) 回调地址；反向代理应正确设置 Host 和 X-Forwarded-Proto。下单自动传递 `/payments/callback/{渠道代码}?channel_id={渠道ID}`，不需要自行构造。支付页面由 UPAY PRO 承载，桌面与手机均跳转到其 `payment_url`，支付后返回商城对应订单或充值页。

## 到账与异常处理

- JSON 回调必须验签成功，商户支付单号、渠道实例、网关交易号、原始 CNY 金额均匹配，并且 `status=2`，才推进到账。
- `actual_amount` 是链上实付金额（可能含网关递增尾数），不能用于 CNY 入账。会员充值按本地本金和赠送入账；供货充值沿用供货账户账务流程。
- 状态 1/3 的合法通知仅应答 `success`，不入账；重复成功通知仍校验金额和交易身份，但不重复发货或充值。
- 同一业务单、同一渠道重复点击复用持久化支付尝试和缓存收银台地址，不延长付款期限；并发请求受数据库租约保护。
- **请求结果不确定时不自动重复下单**。后台「待核对」记录会显示原商户单号。管理员应在 UPAY PRO 后台核对该单：若已收款，使用网关补单/重新通知；若待付款，核实原收银台；若确定未建单或未收款，按实际情况重新安排付款。不要让顾客盲目重复支付。
- 请求失败后收到有效成功回调，仍可正常到账并清除该次下单不确定标记。
- 业务订单已关闭或已由另一笔支付完成后，迟到款记录为已收款、待核对，不再次发货。充值单已经到账时，其他支付尝试收到的款也进入待核对，不二次加余额。
- 有未确认支付或待核对记录时禁止修改网关、密钥、币种/网络等配置。更换配置请新增渠道。
- 渠道先停用再删除；删除隐藏渠道，保留原身份及凭据以接收历史回调，重新添加不会占用旧身份。

## 查单与退款边界

UPAY PRO 的 `GET /pay/check-status/{trade_id}` 是收银台状态查询，只返回 `status`，没有金额、商户单号或签名。本接入不会把这个状态当成独立到账凭据；商城支付页轮询本地已验签处理的支付结果。漏通知应在网关核实并重新发送签名回调。

该版本没有原路退款 API，因此未声明自动原路退款能力。退款按商城现有人工/余额退款流程处理，链上退币需要人工核对并执行。

## 上线验收

用真实 UPAY PRO 做小额验收：核对钱包与汇率 → 下单选对币种网络 → 付款后确认回调到账与发卡/充值 → 再通知一次确认不会重复入账。结果不确定时不要让顾客盲目重复付；到后台「待核对」与网关后台对照。

### 多链支付的复用与换链

同一业务订单、渠道及币种网络复用原支付单与收银台；切换网络使用独立的网关商户单号，切回时仍复用原网络的有效链接。旧版没有网络快照的支付单按原固定网络识别。费用报价也绑定选择，换链需刷新报价。

上游请求进行中或结果未知时禁止绕过原请求换链重试。已取得其他网络的收银台链接仍可能有效；顾客只应完成其中一笔付款。多个网络都收到款时仅履约或充值一次，额外到账保留并进入待核对。存在未确认支付时仍保留原渠道配置，以保证历史回调可处理。
