# 订单处理

---

![订单管理](/images/admin-order.png)

*界面说明：* 「订单列表 / 待发货」页签；按订单号或联系方式搜索；状态快捷筛选（待支付→已退款）。到账但系统仍待支付时可用「补单」手工推进（不向渠道查单）。

## 后台入口

**订单** 菜单：按订单号、邮箱、状态、时间筛选；查看支付单、发卡结果、退款与备注。

前台：会员中心订单列表；游客凭订单号 + 查询密码或邮箱验证码查单（取决于你的安全/交易设置）。

---

## 常见状态（概念）

| 状态概念 | 含义 |
|---|---|
| 待支付 | 已下单未付款；超时可能关闭 |
| 已支付 / 处理中 | 已收款，正在发卡或等上游 |
| 已完成 | 虚拟货已交付或实体已完结 |
| 已取消 / 已关闭 | 未付或超时等 |
| 退款相关 | 部分/全额退款中或完成 |

界面文案以你当前版本为准。

---

## 站长日常操作

1. **查单**：用户反馈未到货时，先对订单号 → 支付回调是否成功 → 发卡/上游单号。  
2. **补发 / 重发**：仅在确认已收款且库存允许时操作；注意审计。  
3. **退款**：站内退余额或标退款后，第三方原路退需在支付渠道后台另做（多数渠道文档已说明）。  
4. **实体发货**：填写快递信息或标到付；到付运费不计入线上实付时，以订单备注/标记为准。

---

## 与支付、货源的关系

| 情况 | 先看哪 |
|---|---|
| 显示已支付但无卡密 | 库存是否为空；是否上游采购失败；发货方式是否改过 |
| 用户说付了系统未到账 | 支付渠道后台流水 ↔ 本站支付单；回调 URL、站点地址 |
| 上游已扣款本站失败 | 订单待核实/人工核查；不要让用户重复付款 |

支付专题：[支付总览](../payment/) · 货源：[货源对接](./supply.md)

## 游客查单

在 **系统设置 → 交易 / 安全 / 通知** 中配置：

- 是否需要查询密码  
- 是否允许邮箱验证码查单（需 SMTP 正常）  

改完用游客测试单验证整条链路。
