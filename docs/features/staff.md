# 员工与权限

后台 **员工管理**（`/staff`）：员工账号为主轴，角色与权限点在抽屉里配置（无需独立「角色页」）。

---

![员工管理](/images/admin-staff.png)

*界面说明：* 员工列表为主轴；行内「权限」改的是该员工所属**角色**（同角色全员生效）。另有「角色管理」抽屉、重置密码、启停账号。

## 能做什么

| 操作 | 说明 |
|---|---|
| 新建员工 | 用户名、初始密码、昵称、角色 |
| 编辑 | 改昵称、换角色 |
| 启用/停用 | 停用后无法登录后台 |
| 权限 | 打开该员工所属角色的权限树并保存 |
| 角色管理 | 抽屉内新建/编辑/删除角色 |
| 重置密码 | 管理员代重置 |
| 解绑 TOTP | 员工丢了验证器时，有权限可解绑后让其重绑 |
| 删除 | 非超管账号可删（以后台校验为准） |

列表可按「全部 / 已启用 / 已停用」筛选。超管账号一般有特殊标记，删除受限。

---

## 权限怎么理解

- 权限挂在 **角色** 上；员工绑定角色后生效。  
- 改了角色权限，**同角色所有员工立刻受影响**。  
- 菜单是否出现、页签是否可写，都由权限点控制（如 `supply:read`、`ticket:write`）。

自己改自己的两步验证：到 **系统设置 → 安全** 或账号安全组件；详见 [两步验证](../operations/security-2fa.md)。

---

## 建议

1. 不要多人共用一个超管号；按岗建角色（客服 / 运营 / 财务只读等）。  
2. 客服通常需要：订单读、工单读写、部分钱包只读——按最小权限给。  
3. 离职立即停用账号，必要时解绑 TOTP 并改相关机器人 Token。
